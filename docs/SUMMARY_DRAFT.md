## 1. ภาพรวมงานแต่ละส่วน (15)
**ทำได้ถึง:** ระดับ 1 + 2 + 3 + โบนัส (หน้าสถานะ pipeline)  ← แก้ตามจริง

- **Extract:** scraping ด้วย requests + BeautifulSoup (ไม่ใช้ Selenium) ตรวจ robots.txt ก่อนดึงทุก URL, หน่วง 1.5 วิ/หน้า, เก็บเฉพาะข้อมูลสินค้า (PDPA)
- **TaskGroup `sources`:** 3 แหล่งรันขนาน แต่ละแหล่ง extract → transform
- **Transform:** แปลงเป็น schema เดียว (title, author, isbn, price, list_price, discount_pct, url ...)
- **merge (`trigger_rule=all_done`):** แหล่งที่ล่มถูกข้าม รวมเฉพาะที่สำเร็จ
- **ตัดซ้ำข้ามร้าน:** ISBN → ถ้าไม่มีใช้ชื่อเรื่อง normalize + fuzzy match (เลขเล่มต้องตรง) → `books_unified`
- **quality_check (`@task.branch`):** ผ่าน ≥80% → `load_postgres` (UPSERT) / ไม่ผ่าน → `quarantine_batch`
- **Load:** `INSERT ... ON CONFLICT (source, source_id) DO UPDATE` รันซ้ำจำนวนแถวไม่เพิ่ม
- **Dashboard (Flask อ่าน PostgreSQL ตรง):** KPI 6 ตัว, ตัวกรอง (ร้าน/ช่วงราคา/ค้นหา/ส่วนลด/เรียง), กราฟราคาเฉลี่ยตามร้าน + histogram ราคา, หน้าเทียบราคาข้ามร้าน, หน้า `/status`

## 2. ปัญหาที่พบและวิธีแก้ (10)
**ปัญหา 1: เว็บนายอินทร์ดึงข้อมูลไม่ได้**
- อาการ: request หน้าหมวดถูกปฏิเสธ (client error) และหน้าแรกโหลดสินค้าด้วย JavaScript
- หาสาเหตุ: เปิด robots.txt พบห้าม `/search-result`, `/api/v1`; ดู HTML ที่ได้ไม่มีรายการสินค้า → ต้องใช้ browser ซึ่งโจทย์ห้าม Selenium
- แก้: เปลี่ยนเป็น Amarinbooks (WooCommerce, ราคาอยู่ใน HTML) และทำ config ให้เปิด/ปิดแหล่งได้ผ่าน `ENABLED_SOURCES`

**ปัญหา 2: ตัดซ้ำข้ามร้านรวมเล่มต่างกันเป็นเล่มเดียว**
- อาการ: ทดสอบ 80 เรื่อง เหลือหลังตัดซ้ำแค่ 60
- หาสาเหตุ: ไล่ดู cluster พบ "ตอนที่ 1" ถูกจับคู่กับ "ตอนที่ 10–19" เพราะกฎ substring
- แก้: บังคับให้ตัวเลขในชื่อเรื่อง (เลขเล่ม/ตอน) ต้องตรงกันก่อนจับคู่ → ได้ 80 ถูกต้อง

**ปัญหา 3: quality check ไม่ผ่านทั้งที่ข้อมูลดี**
- อาการ: branch ไป `quarantine_batch` ทั้งที่ invalid = 0
- หาสาเหตุ: ดู XCom ของ merge พบ valid_ratio = 0.75 เพราะหนังสือเล่มเดียวอยู่ใน 2 หมวดของ Amarin ถูกนับเป็นแถวเสีย และตัวหารรวมแถวซ้ำ
- แก้: ตัดแถวซ้ำในร้านเดียวกันทิ้งเงียบ ๆ และคิด ratio = valid / (valid + invalid)
